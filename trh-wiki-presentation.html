02 / 08
Inspiration

Andrej Karpathy's LLM Wiki Pattern

💡

Core Idea

Instead of re-synthesizing knowledge on every query like RAG, build a compounding wiki that LLMs actively maintain. Knowledge is linked at ingest time, not query time.

Three-Layer Architecture

raw/
Immutable source documents — never edit
wiki/
LLM-written and maintained markdown
CLAUDE.md
Schema — defines structure and workflows

Three Core Operations

ingest
Process new source → auto-update relevant pages, build cross-references
query
Search wiki → synthesize answer with inline citations → save valuable Q&A as new pages
lint
Detect broken links, orphan pages, contradictions, unsourced claims

Karpathy's research wiki grew to ~100 articles and 400,000 words.
Realizing Vannevar Bush's 1945 Memex concept — through LLMs.

03 / 08
Structure

trh-wiki Directory Structure

raw/ Read-only source zone. New docs go into inbox/. Never edited.
wiki/ Entirely LLM-written. Humans read, LLMs write and cross-reference.
CLAUDE.md Schema file. Defines ingest, query, lint operations and conventions.
log.md Append-only operation log. Every ingest, query, lint is recorded.

Wiki Page Conventions

--- updated: 2026-04-09 sources: - raw/inbox/crosstrade-pitfalls.md related: - "[[deposit-tx]]" - "[[cross-trade]]" - "[[separate-compose-for-crosstrade]]" tags: [troubleshooting] --- # L1 Deposit Tx CrossTrade — 13 Pitfalls One-paragraph summary of this page... ## Pitfall 1: ... See [[deposit-tx]] for the base pattern.
🔗
Internal links use [[page-name]]
Obsidian wiki-link format — filename only, no path prefix
📎
Every claim cites a raw/ source
All facts traceable back to an original source file
📝
Present vs. past tense
Current state → present tense · Past decisions → past tense
🚫
What NOT to capture
Things readable from code, git history, resolved debugging steps
✅
What TO capture
Why decisions were made, non-obvious constraints, cross-repo interactions, known failure modes

Automation & Roadmap

Daily Automation Pipeline

1

Scheduled repo change detection

openclaw scheduler checks recent commits and PRs across all TRH repositories at a fixed daily time

2

Collect changes → drop into raw/inbox/

Diffs, PR descriptions, and merge commit messages are saved as source files in raw/inbox/

3

Run ingest operation

LLM analyzes each source, identifies affected wiki pages, updates content and cross-references automatically

4

Commit & push

Updated wiki pages and the new log.md entry are committed and pushed automatically
